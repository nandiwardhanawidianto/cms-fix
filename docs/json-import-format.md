# JSON Invitation Import

The JSON importer is a one-time data-entry shortcut. After import, the normal CMS database is the source of truth and staff edit the invitation normally.

## Workflow

1. Open **Management Undangan**.
2. Click **Import JSON & Buat Undangan**.
3. Paste the JSON from ChatGPT.
4. Preview the generated invitation name, slug, Shopee order number, theme, mempelai, events, love gift, and gift-delivery data.
5. Choose a theme when the JSON has no theme.
6. Create the invitation.
7. Open **Hero & Invitation** only when you need to choose or change photos.

JSON import exists only on the homepage. It is intentionally not available inside an individual slug edit page.

## Slug and order number

- `order_number` is required and is stored in `slug_lists.keterangan`.
- `mempelai_1.short_name` is required.
- `mempelai_2` is optional; when it exists, its `short_name` is required.
- Invitation name is generated in order from the short names.
- Example: `Nanda` + `Ane` becomes **Nanda Ane**.
- The slug is generated by the existing `SlugList` model, for example `nanda-ane`.

## Mempelai ordering

The importer is order-based, not gender-based.

- First person in the customer form becomes `mempelai_1`.
- Second person becomes `mempelai_2`.
- The importer never guesses male/female from a name.
- The old database columns named `pria` and `wanita` remain only as legacy storage slots.

  "theme": null,

    "full_name": "Febri Mananda",

    "parents": "Anak ke 4 dari Bapak Ali Muzahir (alm) & Ibu Risnawati"

  "mempelai_2": {

    "short_name": "Ane",

Unknown top-level keys are rejected instead of silently ignored.

## Picture 1 and Picture 2

The homepage **Picture Default** manager stores two reusable images:

- **Picture 1**
- **Picture 2**

They are not tied to gender and are not tied to Mempelai 1 or Mempelai 2.

Inside **Hero & Invitation**, each mempelai independently has three ways to change the photo:

- **Choose File** — upload and crop a customer photo.
- **Picture 1** — use the first reusable image.
- **Picture 2** — use the second reusable image.

If staff makes no photo selection, the current photo remains unchanged.

Replacing Picture 1 or Picture 2 updates invitations that reference that shared picture. It does not overwrite custom uploaded photos.

For backwards compatibility, old shared files named `pria.*` and `wanita.*` are treated as the legacy versions of Picture 1 and Picture 2 until they are replaced.

## Import behavior

- A valid theme is required before final import.
- `events` supports up to three events.
- `love_gifts` supports up to three accounts.
- Bank names must already exist in Master Bank.
- Event dates use `YYYY-MM-DD`.
- Account numbers and phone numbers remain strings so leading zeroes are preserved.
- JSON does not upload photo files.
- All supported records are created inside one database transaction.

## Current schema limitation

`Turut Mengundang` still has no dedicated field/table in the current CMS schema, so the importer does not silently place it into an unrelated column.
